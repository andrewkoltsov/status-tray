# Status Tray

A small cross-platform tray app (Tauri 2, Rust) that watches public status pages (GitHub,
Cloudflare, OpenAI, ...) and raises a desktop notification when something changes, so you find out
GitHub is down *before* your push hangs. The tray icon shows the worst current state; the menu links
to the latest incident of each service.

See [docs/SPEC.md](docs/SPEC.md) for the full specification.

> Status: initial skeleton. The bundled `services.json` catalog is currently **empty**, because
> no status page could be verified from the environment that generated the skeleton. Run
> `python3 scripts/verify_services.py --candidates` on a networked machine and add the ones that
> pass (see below).

## Layout

```
Cargo.toml            workspace
services.json         service catalog (data, bundled into the binary)
crates/status-core/   pure logic: model, catalog, providers, diff, notification text (unit-tested)
src-tauri/            app shell: tray, scheduler, notifications, settings store, IPC
ui/                   settings window (plain HTML/CSS/JS, no bundler)
scripts/              icon generator, catalog verifier
```

## Development

Requirements: Rust (stable), and on Linux the Tauri system libraries:

```sh
sudo apt-get install libwebkit2gtk-4.1-dev libgtk-3-dev libayatana-appindicator3-dev \
  librsvg2-dev libssl-dev libxdo-dev build-essential pkg-config
```

```sh
cargo install tauri-cli --version "^2" --locked
cargo tauri dev          # run the app (tray icon + hidden settings window)
cargo tauri build        # bundle for your OS

cargo test -p status-core
cargo clippy --workspace --all-targets -- -D warnings
```

No Node toolchain is needed. `RUST_LOG=debug cargo tauri dev` for logs.

On GNOME the tray icon needs the AppIndicator extension.

Icons are generated by `python3 scripts/gen_icons.py` (needs Pillow).

## Adding a service

Add one entry to [`services.json`](services.json) and open a PR. No code needed for services
running Atlassian Statuspage:

```json
{ "id": "github", "name": "GitHub", "type": "statuspage", "url": "https://www.githubstatus.com" }
```

- `id`: unique, `[a-z0-9-]+`, never changes (it is the settings/state key).
- `type`: provider, one of `statuspage`, `google-cloud`, `aws-health`, `rss-active`.
- `url`: `https` URL. Its meaning depends on `type`:
  - `statuspage`: site base URL; the app reads `<url>/api/v2/summary.json`.
  - `google-cloud`: site base URL (`https://status.cloud.google.com`); reads `<url>/incidents.json`.
  - `aws-health`: site base URL (`https://health.aws.amazon.com`); reads `<url>/public/currentevents`.
  - `rss-active`: the **full feed URL** (RSS or Atom). Every entry is an active incident;
    an entry disappearing means resolved.
- `params` (optional object, provider-specific filters):
  - `google-cloud`: `"locations": ["europe-"]`, location id prefixes. Incidents without a
    specific location are global and always kept.
  - `aws-health`: `"regions": ["eu-", "us-east-1"]`, region code prefixes.

Verify the entry first (`python3 scripts/verify_services.py https://your.status.page`), then run
`cargo test -p status-core`, which validates the whole catalog.

## Unsigned builds

Release builds are not code-signed yet.

- **macOS**: Gatekeeper says the app "is damaged" or "cannot be opened". Move it to
  Applications, then right-click > Open, or run `xattr -dr com.apple.quarantine "/Applications/Status Tray.app"`.
- **Windows**: SmartScreen shows "Windows protected your PC". Click *More info* > *Run anyway*.
- **Linux**: AppImage needs `chmod +x`; `.deb` installs normally.

## Manual test checklist

The app shell has no automated tests; check these by hand (use a 1 minute interval).

- [ ] First start: no window or Dock icon (macOS), tray icon appears, grey until the first check.
- [ ] Tray menu lists enabled services with a status line; clicking a row opens the incident or status page.
- [ ] "Check now" updates "Last check".
- [ ] Settings...: window opens; closing it hides it, the app keeps running; second launch re-focuses it.
- [ ] Enable/disable a service: tray menu updates; no notification for the initial state.
- [ ] Change the interval, quit, restart: setting persisted. Same for enabled services.
- [ ] Incident opened / updated / resolved on a watched page: one notification each, icon colour follows
      (point a catalog entry at a local mock `summary.json` server to simulate).
- [ ] Restart while an incident is open: no repeated notification.
- [ ] Go offline: after 3 failed checks the service shows "unreachable", no notification;
      back online it recovers.
- [ ] "Launch at login" toggle: enabled after re-login (macOS, Windows).
- [ ] Update notice appears when a newer release exists.

## Notes

- Test fixtures in `crates/status-core/tests/fixtures/` are hand-written to the Statuspage schema, not
  captures of real pages (see the README there).
- Notification click-to-open is not reliable with the Tauri notification plugin across desktops, so
  incident links live in the tray menu.
- Tray icons are coloured circles; macOS template-style monochrome icons are not done yet.
